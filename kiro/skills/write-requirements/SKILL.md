# Escrever requisitos

1. Leia `business-brief.md` e preserve objetivos e limites.
2. Modele comportamentos como requisitos `REQ-nnn`.
3. Escreva critérios `AC-nnn` observáveis; prefira dado/quando/então para fluxos.
4. Inclua regras `BR-nnn`, casos de erro, limites e permissões.
5. Defina requisitos não funcionais `NFR-nnn` com medida ou condição verificável.
6. Liste explicitamente o que permanece fora do escopo.
7. Atualize a matriz objetivo -> requisito -> critério em `requirements.md`.
8. Revise ambiguidade, conflito, duplicação e solução técnica indevidamente prescrita.

## Conclusão

Cada requisito deve ser compreendido sem contexto oral e deve permitir que testes determinem aprovação ou falha.
